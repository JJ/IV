# Project Context and High-Level Decisions

This file records high-level decisions regarding the documentation and procedures in this repository.

## Documentation Style & Tone
- **Primary Tone**: Documentation must refer to the reader consistently in the **3rd person singular** as "el estudiante" (e.g., "el estudiante debe realizar..."). Avoid using 2nd person singular ("tú") or 2nd person plural ("vosotros").
- **Language**: Spanish. Pay close attention to proper grammar, punctuation, and avoid literal translations from English (e.g., use "preguntas frecuentes", not "preguntas frecuentemente preguntadas").

## Academic Procedures & Evaluation
- **Problem Ownership**: Students will propose and develop a project based on a problem. While they must propose an idea they are comfortable working with, they will participate in peer-review and may work on another student's problem for specific objectives (like Objective 2).
- **Deliverables (Pull Requests)**: When students are required to deliver an objective via GitHub, they must create a branch, open a Pull Request (PR) from that branch, and submit the **URL of the PR** (not the URL of the branch).
- **Failure Conditions (Convocatoria Ordinaria)**: The initial objective (Objective 0) is blocking. If a student fails to pass Objective 0 on time, they **fail the ordinary call entirely**. They may continue submitting subsequent objectives solely to prepare for the extraordinary call.
- **AI Policy**: Students must write their own code and business logic. The use of generative AI to generate algorithm implementations or write the documentation is considered a serious violation.
